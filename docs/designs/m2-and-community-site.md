# M2 adapter and community website design

This work executes the approved M2 direction in specifications.md and prepares a local website for teams that want to evaluate or contribute. No public deployment, external messages, real calls, paid models, or hosted migrations are authorized in this slice.

## M2 private integration

Keep Receptionaly-specific schemas, source pointers, provisioning, and readers in a sibling private adapter directory. Implement the published ReceptionBenchAdapter lifecycle and a neutral process boundary usable by additional vendors. Provision only marked synthetic namespaces on a disposable loopback database. Validate fixtures and keep the oracle out of provisioning and requests. Source services may be imported read-only by the private package; no source or history is redistributed.

Initially verify local persistence and directory/routing behavior. Declare unavailable delivery, booking mutation, voice transfer, return media, and executed callback evidence explicitly. Local database checks are adapter conformance and service integration evidence, not a scored voice-system benchmark. Independent scoped reads reconcile persisted results. Cleanup is idempotent, ownership-checked, and verified after failures. No global environment file or paid-provider credentials are loaded.

The public CLI will expose safe adapter conformance through an explicit process command, without importing private code. Local-only capability checks receive business fixtures and trial context only. Require explicit local-integration opt-in and reject fixture receipt mismatch or malformed responses. The existing fake-only scored runner stays unchanged until a real caller/evidence transport exists.

## Community website

Audience: developers and teams building receptionist/voice-agent systems. Initial purpose: explain business-outcome measurement, show why evidence matters, and help teams run the local core or contribute a vendor adapter. Broader agent domains remain a future extension unless the user changes the brief.

Use a lightweight responsive static website in website/, with no backend or external tracking. A clear editorial layout leads from the problem to interactive evidence examples, methodology, current capabilities, and participation instructions. Present simulations as simulations. No fabricated vendor rankings, participant logos, endorsement, certification, published repo links, or contact inboxes. GitHub/contact destinations become configuration once provided; useful contribution instructions and a downloadable participation brief work without those destinations.

Include working case filtering or an evidence explorer, methodology content, quickstart, adapter checklist and a participation brief. Clearly disclose that Receptionaly is the initial reference system and independent hidden custody/second vendor are pending. Add CONTRIBUTING.md, adapter guidance and a protocol for voluntary vendor participation. Authors receive the same suite and scoring rules; vendor telemetry does not establish recipient outcomes.

Build and preview locally. Public release requires ownership/license clearance, a configured repository/contact destination and an explicit publication decision. No outreach is sent. No scores are submitted to a leaderboard.
