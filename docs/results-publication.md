# Results publication

The website consumes `website/results.json`. The initial registry is empty. Entries are reviewed repository changes, not anonymous submissions or endorsements. `ResultsRegistrySchema` runs in the normal offline suite; it checks publication/review fields, count and cohort consistency, public-data boundaries and safe artifact URLs. Schema validity does not authenticate external outcomes or establish reviewer independence.

The current schema permits only unranked results from real declared transports. Offline fake-adapter reports and unscored readiness checks do not become system performance entries. Numerical ranks remain disabled until reviewed frozen cohorts, repetitions, completion gates and aggregate uncertainty are implemented under M4. Keep suite/evaluator/profile/transport/language/caller/observation/track digests distinct; never sort incompatible cohorts together.

Before opening a result PR:

1. Obtain the participant's publication permission and record its reviewable reference/date.
2. Freeze the system version (or label it opaque), configuration, protocol and scheduled attempts. Preserve failures and predeclared infrastructure-replacement rules.
3. Review independent outcome receipts and replay the private normalized bundle. Publish a redacted report with its digest; document controlled reviewer access to restricted evidence.
4. Record every scheduled verdict, evidence coverage, critical violations, per-scenario intervals and completion. A smoke result needs its small sample size prominently disclosed. Do not claim a zero-violation sample proves safety.
5. Record observed costs and billing uncertainty. Disclose caller limitations and all operator/developer relationships. Distinguish self-reported, benchmark-operated and independently audited evidence; none automatically confers certification.
6. Remove phone numbers, tokens, raw messages/transcripts, private endpoints and hidden cases from public artifacts. Keep artifact links HTTPS without credential-bearing query strings.

Receptionaly is the initial reference system. Until independent operation exists, its developer-operated runs are internal research. A second vendor/domain, independent hidden-bank custody and the remaining milestone requirements are prerequisites for independent benchmark claims.

The first pilot appears only after a separate result review and agreed publication scope. Preserve superseded records and explain evaluator corrections; rescore all affected systems consistently. Public contributors can propose adapters, synthetic cases and evaluator counterexamples through GitHub issues now.

When publishing the first entry, update the static empty-state text alongside the registry so the baseline remains accurate without JavaScript. The browser only renders reviewed records; it does not independently verify provider evidence.
