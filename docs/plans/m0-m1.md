# ReceptionBench M0 and M1 implementation plan

Goal: independently authored offline benchmark vertical slice under specifications.md.
Architecture: shared strict schemas → frozen planner → fake adapter/caller → authenticated local collectors → durable SQLite evidence → deterministic assertion engine → category scorer → JSON/HTML and replay.
Execution: inline in the supplied new repository. It has no Git checkout or existing code requiring worktree isolation. No original repository content or history will be imported.

- [x] M0: record source revision/dirty paths; inspect capability and test definitions; inventory tests without imports; classify reuse and migration; write private audit outside distribution.
- [x] Contract: write failing malformed-schema/trust-boundary tests; implement strict TypeScript schemas, JSON Schema generation and fixture/reference/profile validation.
- [x] Evidence/evaluator: write truth-table and hostile-evidence tests; implement authenticated ingress, deduplication, SQLite snapshots, missing-versus-observed-absence rules, forbidden effects, multiplicity and timing.
- [x] Offline execution: test ten distinct synthetic cases and injected failures; implement fake lifecycle and caller driver without oracle access, frozen plans, zero-cost admission, cleanup and manifest hashes.
- [x] Reporting: test category weighting and unsupported/exclusion denominators; implement scores, Wilson intervals, JSON/escaped HTML and deterministic replay.
- [x] Verify: typecheck, full test suite, schema validation, fake conformance, ten-case run, failure runs and replay; inspect source checkout remains unchanged.

Review focus: self-declared authority, cross-trial/tenant evidence, conflicting duplicates, falsely complete observation windows, mutated plans/bundles, unsupported full-profile scenarios, failed teardown, HTML injection. Tests must pin each boundary.

M1 deliberately has no REST server, real transport/model, private adapter, live callback verifier or hidden bank. M4 adds independent-trial bootstrap and paired statistics; simulation outcomes cannot establish model/media quality or independent certification. New code ownership and fixture license are pending review; no license grant is applied.

## Execution record

M0 private artifacts were completed before product code. Contract and evaluator tests were written first, observed failing, then implemented. Runner/CLI and hostile-evidence regressions followed the same cycle. Final checks: 32 passing tests with network guards; ten-case CLI run and identical replay with only PATH in the child environment.

Ruling: use the installed SQLite executable with argument-only calls rather than a native npm binding; this avoids unavailable registry packages while preserving transactional durable storage. The runtime dependency is explicit in doctor/README.

Ruling: keep the source-specific audit outside the new repository, including the private migration matrix and full test index. Only the portable M0 summary is included here.

Ruling: process resume, hosted API, live transports, independent state readers and aggregate scenario bootstrap belong to dependent milestones, not this offline slice. Checkpoints are retained for inspection, not advertised as resume support.

Review fixes: prohibit all booking mutations; keep vendor crashes in valid denominators; require distinct transfer legs; reject forged clocks; validate predicate value types and fixture/caller/capability contracts.
