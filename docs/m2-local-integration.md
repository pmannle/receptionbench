# M2 local reference integration: verified scope

The private reference adapter and public process boundary are implemented. Two isolated database profiles have been exercised: a historical directory/routing slice and the current active migration chain. These are local service integration results; neither profile provides a scored voice benchmark.

| Surface | Verified current-profile evidence | Boundary |
| --- | --- | --- |
| Database | All 87 active application migrations with actual cached infrastructure schemas; four original SQL suites | One source-gated manual retirement draft excluded; no hosted migration |
| Business facts | Original native instruction/account readers, hours and nondefault timezone | Retrieval only; production prompt assembly and spoken answers unverified |
| Onboarding | Original review, confirmation, activation and readiness services | Bounded local SQL transport under service role; no signup HTTP/auth/RLS claim |
| Routing | Original lead service selects current routing transaction; expected recipient, one durable lead and two events | Local persistence; no provider worker or message delivery |
| Fixture lifecycle | Exact native mapping, idempotent preparation, tamper detection and ownership checks | Synthetic isolated fixtures; no answered endpoint |
| Cleanup | Independent zero-row reconciliation and owned sandbox disposal | No real call legs existed |
| Public SDK boundary | Public CLI process conformance against both private profiles | Adapter lifecycle only; no task score |

The current profile declares local `business.info`, `routing.team` and `booking.link`. The historical profile declares only local `routing.team` and `booking.link`; its hours/timezone remain metadata. Neither profile declares delivery, callbacks, transfers, return media or booking mutations verified. Policies and endpoint references remain benchmark metadata, not evidence of native policy enforcement or live endpoints.

Thirteen private tests, four original SQL suites, native source integration and public process conformance have passed in the current profile. Source services execute unchanged from the read-only reference checkout. Private fixture provisioning uses a disposable database administrator; source-client operations use the database service role. Full API/HTTP transport, authentication/RLS, production prompt assembly, provider execution and voice/media remain unverified.

Source-specific mappings, migration details, source pointers and integration evidence remain in the private companion repository. The public benchmark imports no reference-system implementation. The original checkout revision and existing changes were preserved.

M3 adds authorized caller transport, controlled receiving endpoints, authenticated receipts, budgets and reconciled cleanup before real voice outcomes are scored.
