REQUIRED OUTCOME

Consent + correct recipient + received link + no forbidden effects

A booking-link handoff needs consent and a receipt at the caller’s controlled destination. It does not establish that an appointment was created.

02 / THE METHOD

Measure the task.
Keep the proof.

A vendor-neutral contract defines the outcome. Adapters connect systems to that contract without prescribing their internal tools.

01

Set the business context

Fresh synthetic business facts, a caller goal and an explicit policy. Expected outcomes stay with the evaluator, outside the system under test.

02

Observe the real effect

Check the recipient, state change or media path. A sent booking link is a handoff; creating an appointment requires a separate profile and booking evidence.

03

Report the whole result

Retain failures, missing evidence and unsupported tasks. Show coverage and critical violations alongside success counts. Rescore recorded evidence deterministically.

↳

There can be several correct ways to complete a task.
The outcome matters more than the tool sequence.

03 / FIELD NOTES

Useful today.
Honest about tomorrow.

The offline core helps developers inspect and challenge the verifier. Real voice evaluation needs additional transport, outcome observers and independent operation.

REFERENCE SYSTEM DISCLOSURE

Receptionaly is the initial reference system. A second vendor adapter and independent hidden-test custody are pending. This project does not currently offer independent certification or a verified vendor leaderboard.

  1. M0–M1
    AVAILABLE LOCALLY

    Audit + offline core

    Ten synthetic cases, fake adapter, deterministic evaluator, evidence replay and reports. Simulated receipts only.

  2. M2
    IN DEVELOPMENT

    Private reference adapter

    Isolated fixture mapping, lifecycle conformance and local integration. Conformance is distinct from a scored voice-system benchmark.

  3. M3–M4
    PLANNED

    Voice transport + pilot

    Controlled counterparts, authoritative delivery and media evidence, reviewed scenarios and repeated trials.

  4. M5–M6
    PLANNED

    Independent beta + release

    Second vendor and domain, independent hidden custody, licensing clearance and reproducible public reporting.

04 / AT THE BENCH

Start with a fake system.
Learn something real.

Run the local offline core, inspect an evidence bundle and replay its verdicts. No credentials or live calls required.

FROM AN EXISTING CHECKOUT

A small, inspectable loop.

Use Node 18.20.8, npm 10.8.2 and sqlite3 on your PATH. Dependency installation may need network access; subsequent offline runs do not.

Choose a fresh output directory for each run. This demonstration evaluates the fake adapter and verifier, not a production receptionist.

LOCAL / OFFLINE SIMULATION○ ○ ○
npm ci --ignore-scripts
npm run build
npm test
node dist/src/cli.js doctor
node dist/src/cli.js adapter check --adapter fake
node dist/src/cli.js plan --out run-plan.json
node dist/src/cli.js run --plan run-plan.json \
  --offline --out runs/demo
node dist/src/cli.js replay \
  --bundle runs/demo/bundle.json
